## Reload-restore (verified against the live Hermes gateway 2026-08-13)

- Documented endpoint that WOULD replay the transcript: Hermes API server
  Sessions API `GET /api/sessions/{id}/messages` (docs
  /docs/user-guide/features/api-server). Verified live: returns the full
  user/assistant/tool history for a session.
- Why it cannot be used from the web app today: the session id it needs is
  Hermes-generated (`uuid4`) and is never exposed to Frank — the W2-1 turn
  API persists only `{profile, session_key}`, does not forward
  `X-Hermes-Session-Id` (which IS returned by Hermes), and the id is not
  derivable from the session key. Wiring it would require an apps/api
  change (out of W2-2 scope; see hot-file request C below).
- Degradation implemented (sanctioned by the packet): same `session_key`
  chains turns in the same Hermes conversation, so reload keeps context;
  the UI renders a "conversation continues" note instead of fabricating a
  transcript. `conversationRestoreNote()` documents this in code.
