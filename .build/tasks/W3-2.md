## What landed

- `apps/api/src/routes/skills.ts` (new) — TWO declared, registered routes:
  - `GET /v1/skills` — the list. Every skill directory under the skills root
    (`FRANK_SKILLS_ROOT`, default `C:\Users\steve\AppData\Local\hermes\skills` —
    Hermes' own store, READ ONLY; nothing in this module writes) with `id`,
    `name` (folder name), `description` (frontmatter via **gray-matter**, or the
    first paragraph when a skill has no frontmatter — e.g. `hello-world`),
    `path`, and `frontmatter_error` (null when clean).
  - Packet contract honoured: `GET /v1/skills?path=<relative path>` returns ONE
    skill's SKILL.md as `content` (frontmatter stripped) + `frontmatter_error`
    instead of throwing when the YAML is broken.
  - `GET /v1/skills/:id` — the detail endpoint per the dispatch brief; same
    resolver, same payload. `:id` is the skill's relative path (single URL
    segment; slash-encode multi-segment paths — the web client uses `?path=`,
    which is robust through the BFF proxy).
  - Path safety (three checks): id regex (no leading `/`, no `..` segment, no
    backslashes, no drive letters) → realpath containment of the skill dir →
    realpath containment of the `SKILL.md` itself (symlink escape refused).
    Windows-aware `pathIsWithin` (case-insensitive).
  - List reads only the first 8 KB of each `SKILL.md` (frontmatter lives at
    the top); full content is fetched only by the detail paths, capped at 1 MB.
    Bounded depth walk (root + 3), so 145 real skills list in one pass; the
    `computer-use` name collision (root AND `autonomous-ai-agents/`) yields two
    distinct ids.
  - Capability: `brain.search.read` (skills are §8.3 shared memory; every role
    incl. `service_identity` — the BFF service token path). A dedicated
    `skills.read` row in `packages/identity/src/roles.ts` is a coordinator
    follow-up, not required here.
- `apps/api/src/test/skills.test.ts` (new) — 29 tests against a temp fixture

## Notes / deviations from the packet

- `apps/web/package.json` was NOT changed: react-markdown was already a
  dependency; frontmatter parsing lives in the API, so `gray-matter` went into
  `apps/api/package.json` (the only place it is used).
- The packet's `?path=` contract IS implemented (list route + content); the
  dispatch brief's `GET /v1/skills/:id` is the second declared route, sharing
  the resolver. Both are covered by tests.
- Capability: no `skills.read` exists in `packages/identity/src/roles.ts`
  (out of W3-2 scope); used `brain.search.read` — grants every role including
  `service_identity`, matching the BFF service-token path. Follow-up: a
  dedicated `skills.read` row when roles.ts is next touched.
- Gray-matter pitfall discovered (documented in the route): `matter()` caches
  by content string and stores the file object BEFORE parsing, so a YAML
  exception poisons the cache and the next identical parse silently returns
  unparsed data. All calls pass `{}` to bypass the cache.
- Shared tree: W3-1's uncommitted edits (server.ts imports, api-contract count,
  files route/test, web deps, lockfile) were left untouched; my commits add
  explicit paths only.
